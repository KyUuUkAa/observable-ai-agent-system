# 甲骨文资料整理 Agent：3 分钟演示脚本

## 演示前准备

1. 启动 PostgreSQL、Ollama、后端和前端。
2. 打开“甲骨文识别”页面和浏览器开发者工具以外的干净窗口。
3. 准备一张高置信度样例和一张低置信度样例；不得使用测试报告中已知错误来伪装效果。
4. 清空或标记演示产生的记录，避免与真实历史记录混淆。

## 0:00–0:25：问题与定位

口播：

> 这个项目不是自动释读甲骨文，而是帮助资料整理人员处理已经裁剪好的单字拓片。系统先给出六位类别码和置信度；低置信度结果进入复核队列，并提供相似字模和历史拓片作为视觉证据。没有可靠字典时，Agent不会编造现代汉字。

画面：展示单字识别、批量处理与复核两个工作区。

## 0:25–1:05：高置信度识别

1. 上传高置信度样例。
2. 展示 Top-1、Top-5、置信度和模型版本。
3. 点击“交给 Agent 分析”。
4. 展示 Execution Trace 中只调用一次 `recognize_oracle_image`。

口播重点：模型做类别判断；Agent只负责理解请求、调用工具和解释证据。

## 1:05–1:45：低置信度检索与复核

1. 上传低置信度样例。
2. 展示确定性阈值将结果分配到待复核队列。
3. 展示检索返回的相似字模、历史拓片和分类/检索冲突提示。
4. 在复核页确认或驳回记录，并补充备注。

口播重点：检索候选不会静默覆盖分类结果；关键决策由代码阈值约束。

## 1:45–2:20：自然语言资料管理

依次演示两条指令：

```text
找出今天置信度低于0.85的待复核记录。
导出本周出现分类与检索冲突的记录。
```

展示 Agent 调用记录查询和导出工具，以及 CSV/JSON 下载结果。

## 2:20–2:50：真实评估证据

打开“批量处理与复核”页的质量证据区域，指出：

- 300 张独立测试拓片覆盖 109 类；
- Top-1 79.67%，Top-5 95.00%；
- 0.85 阈值自动通过覆盖率 58.00%，通过结果准确率 94.25%；
- 检索 Recall@5 为 60.00%，分类与检索候选集合覆盖率为 95.33%；
- 泄漏审计通过，样本与 train/val 的来源组及内容哈希重叠均为 0；
- Agent 路由回归 60/60 通过。

## 2:50–3:00：边界说明

口播：

> 当前系统面向单字资料整理，类别输出仍是数据集编码；没有经过专家确认的编码字典，因此不声称给出现代汉字释义。下一步价值主要来自真实人员复核实验，而不是继续堆模型。

## 录制原则

- 全程使用真实接口，不剪接伪造成功响应。
- 保留一次低置信度或冲突案例，展示系统边界。
- 不展示 `.env`、数据库密码、令牌、用户隐私或 G 盘原始路径。
- 视频中所有效率数字必须标明“实测系统耗时”或“规划假设”。
